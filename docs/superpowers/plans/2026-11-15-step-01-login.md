# Step 01 — Login and Staff Identity

> **Delivery order:** `docs/roadmap.md`. Work only on this step until Sean approves.
> **Spec:** `docs/spec.md` sections 5, 6, 10.2, 11, 13.1–13.3.
> **Design:** `docs/design.md` sections 4, 7, 8.

**Goal:** A staff member signs in with email and password. The app knows their display name and role. The session survives a refresh. No PIN, no app shell, no shop data.

**Why profiles are included:** a login is useless if the app cannot tell the owner from the mechanic. The profile table is the smallest database piece that makes roles real.

## Interfaces produced

```ts
type Role = 'owner' | 'mechanic';
type Profile = { id: string; displayName: string; role: Role };
type AuthState =
  | { status: 'loading'; profile: null }
  | { status: 'signed-out'; profile: null }
  | { status: 'signed-in'; profile: Profile };

type AuthContextValue = AuthState & {
  error: string | null;
  signIn: (email: string, password: string) => Promise<void>;
  signOut: () => Promise<void>;
  refreshProfile: () => Promise<void>;
};

class AppError extends Error {
  code: 'MISSING_ENV' | 'AUTH_INVALID' | 'AUTH_RATE_LIMIT' | 'AUTH_NETWORK' | 'PROFILE_MISSING' | 'UNKNOWN';
}
```
